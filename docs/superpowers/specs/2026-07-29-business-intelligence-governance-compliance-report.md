## Explicit non-conflations preserved

- `ownerUserId` denormalizes `businesses.ownerId` — it is not a replacement for it, and `businesses.ownerId` remains the source of truth.
- `teamWorkspaceId` (new, inert, reserved for a future generic Team Workspace concept) is never conflated with the pre-existing `client_workspaces` table (agency/white-label client portals — a customer-facing, unrelated concept). No FK exists between them; no code path reads `teamWorkspaceId` as if it were a `client_workspaces` reference.
- `recordVersion` (generic optimistic-concurrency counter, Data Access Layer-owned) is never conflated with `business_dna_claims.version` (a pre-existing domain concept tracking how many times a DNA *value* has changed).
- `governanceStatus` (generic active/archived/deleted lifecycle flag) is never conflated with each table's own domain `status` column (conflict open/resolved/deferred; review open/dismissed/resolved; recommendation new/dismissed/applied/stale) — those keep their original meaning and are read/written exactly as before.
- The Business Timeline's job (narrating business events for a human/AI audience) and the new Audit Trail's job (recording exactly what changed, for compliance traceability) remain two separate tables with two separate purposes — no merge.

## Remaining technical debt & performance impact

See `2026-07-29-business-intelligence-governance-design.md` for the full detail — summarized:

- `ashResearchProfilesTable` and system instances remain intentionally ungoverned (documented Phase B candidates, not gaps).
- `teamWorkspaceId` is inert until a Team Workspace subsystem is designed.
- The stale-recommendation bulk update became a per-row loop for accurate per-record audit diffs — correct at current scale, flagged for revisit if that workload grows much larger.
- Each governed mutation now performs one additional `INSERT` (the paired audit row) in the same transaction — proportional to existing low-frequency BI write volume, with new indexes on `audit_trail_entries` backing both expected query patterns (by business, by record). No new query was added to any read path, and no N+1 was introduced.
