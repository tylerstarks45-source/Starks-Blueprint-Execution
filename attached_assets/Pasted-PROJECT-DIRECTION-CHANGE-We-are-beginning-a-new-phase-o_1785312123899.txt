PRIMARY ARCHITECTURAL LAW

Upgrade Before Replace

Every future task must follow this order:

1. Reuse existing architecture.
2. Extend existing architecture.
3. Refactor existing architecture.
4. Replace only if absolutely necessary.

Replacement is the last option.

Every proposal to replace an existing subsystem must include:

- Why the current architecture cannot support the requirement.
- Benefits of replacement.
- Migration strategy.
- Rollback strategy.
- Compatibility impact.

Otherwise the existing architecture should be extended.
