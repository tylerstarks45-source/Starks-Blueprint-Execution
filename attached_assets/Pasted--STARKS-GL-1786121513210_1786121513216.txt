AI ROUTING POLICY

═══════════════════════════════════════════════════════════════════════

ASH's primary AI routing platform SHALL remain OpenRouter.

The platform has already been integrated.

The OpenRouter API key already exists.

The OpenRouter configuration already exists.

DO NOT replace it.

DO NOT migrate away from it.

DO NOT create duplicate AI routing systems.

DO NOT hard-code OpenAI as ASH's primary provider.

═══════════════════════════════════════════════════════════════════════

REQUIRED ACTIONS

═══════════════════════════════════════════════════════════════════════

Before implementing any future AI-related code:

1.

Audit the existing AI implementation.

Determine:

• where OpenRouter is configured

• where API keys are loaded

• where model routing occurs

• where model selection occurs

• where provider selection occurs

• which services already use OpenRouter

2.

Reuse the existing implementation.

Never duplicate it.

3.

If OpenAI SDKs exist:

Treat them only as implementation libraries if they are already
being used through OpenRouter compatibility.

Do NOT bypass OpenRouter.

4.

All future AI requests shall continue using the existing
OpenRouter routing architecture.

PERMANENT LAW

═══════════════════════════════════════════════════════════════════════

Unified AI Routing Law

ASH shall access AI models through a unified routing layer.

OpenRouter is the platform's primary AI routing provider.

Business domains SHALL request AI capabilities.

The routing layer SHALL determine which model is most appropriate.

No business domain may directly hard-code a specific AI provider
unless explicitly required for a specialized capability and approved
by the Founder.
